# Rise 背包系统程序策划

## 0. 目标与边界

当前 Unity 工程根目录：`E:\数据库\rise\rise\Rise`

本文档说明背包、资源点搜索、物品操作、补给取舍和攀爬系统之间的程序关系。背包系统以《三角洲行动》的网格背包操作为参考，核心体验是“有限空间、重量压力、快速转移、搜索资源、取舍补给”。

设计边界：

- 背包系统服务攀爬路线决策，不做复杂生存模拟。
- 四个长期属性为：健康、饥饿、温暖、理智。
- 体力不是长期属性，体力是短期攀爬资源，基础值 100。
- 背包分为小背包和大背包。
- 小背包 4x4，随时可打开，用于快速使用和临时取舍。
- 大背包 6x6，只能在休息点打开，用于完整整理、烹饪和补给规划。
- 物品有格子形状、重量、堆叠上限、分类、使用时机和效果。
- 背包总重量影响攀爬体力消耗和蹬腿效率。

## 1. 玩家资源结构

### 1.1 短期攀爬资源

| 名称 | 默认值 | 说明 |
|---|---:|---|
| 攀爬体力 | 100 | 抓取、保持、蹬腿消耗；短休息可恢复 |

规则：

- 成功抓取普通点：消耗 2。
- 每只手保持普通抓取：每秒消耗 1。
- 抓取锚点/绳索：消耗 0。
- 保持锚点/绳索：消耗 0。
- 蹬腿：建议每次消耗 4，受背包重量影响效果。

### 1.2 长期状态

| 属性 | 方向 | 主要来源 | 主要影响 |
|---|---|---|---|
| 健康 | 越高越好 | 摔落、温暖过低、饥饿过低、医疗物品 | 归零失败或回到检查点 |
| 饥饿 | 越高越好 | 时间流逝、长路线消耗、食物恢复 | 过低时影响健康和理智 |
| 温暖 | 越高越好 | 高海拔、风区、长时间暴露、燃料/长休恢复 | 过低时影响健康和体力恢复 |
| 理智 | 越高越好 | 长时间低体力、失败、温暖过低、镇定药恢复 | 过低时 HUD 干扰、提示延迟或手部轻微抖动 |

实现建议：

- `PlayerVitals` 保留这些字段，但补充明确接口：`ApplyItemEffect()`、`ApplyExposureTick()`、`ApplyFallDamage()`。
- 长期状态变化频率低于攀爬体力，建议每 5 到 10 秒结算一次环境压力。
- 不要在普通攀爬中持续强行扣健康，健康主要作为惩罚和恢复资源。

### 1.3 四个属性条阶段效果

四个长期属性都使用 0 到 100 数值。健康、饥饿、温暖、理智全部是数值越高越好，降低学习成本。

#### 健康

| 数值阶段 | 阶段名 | 效果 |
|---|---|---|
| 0 | 崩溃 | 玩家失去行动能力，回到最近长休检查点或触发失败结算。 |
| 1-33 | 重伤 | 攀爬体力恢复效果 -30%；蹬腿效率 -15%；HUD 边缘出现受伤提示。 |
| 34-66 | 轻伤 | 攀爬体力恢复效果 -10%；摔落伤害额外 +10%。 |
| 67-100 | 稳定 | 无负面效果；医疗物品可以继续恢复但不能超过 100。 |

#### 饥饿

| 数值阶段 | 阶段名 | 效果 |
|---|---|---|
| 0 | 饥饿崩溃 | 每 10 秒健康 -5；理智 -5；长休无法获得完整恢复。 |
| 1-33 | 严重饥饿 | 每 10 秒健康 -2；攀爬体力恢复效果 -25%；理智自然下降 +1/10秒。 |
| 34-66 | 空腹 | 攀爬体力恢复效果 -10%；长休恢复量 -10%。 |
| 67-100 | 饱腹 | 无负面效果；长休和食物恢复按正常数值结算。 |

#### 温暖

| 数值阶段 | 阶段名 | 效果 |
|---|---|---|
| 0 | 失温 | 每 10 秒健康 -3、理智 -4；保持抓取消耗 +15%；蹬腿效率 -10%。 |
| 1-33 | 寒冷 | 每 10 秒理智 -2；攀爬体力恢复效果 -15%；保持抓取消耗 +5%。 |
| 34-66 | 微冷 | 理智恢复效果 -10%；低体力喘息提示更早出现。 |
| 67-100 | 温暖 | 无负面效果；长休恢复按正常数值结算。 |

#### 理智

| 数值阶段 | 阶段名 | 效果 |
|---|---|---|
| 0 | 崩溃 | HUD 出现强干扰；资源点搜索速度 -50%；手部瞄准轻微持续抖动。 |
| 1-33 | 恐慌 | 交互提示延迟 0.5 秒；资源点搜索速度 -25%；低体力音效更频繁。 |
| 34-66 | 紧张 | 资源点搜索速度 -10%；HUD 状态提示轻微闪烁。 |
| 67-100 | 冷静 | 无负面效果；资源点搜索按正常速度进行。 |

## 2. 背包模型

### 2.1 背包类型

| 背包 | 尺寸 | 打开条件 | 主要用途 |
|---|---:|---|---|
| 小背包 | 4x4 | 随时可以打开 | 快速使用、临时放入、从资源点带走关键物品 |
| 大背包 | 6x6 | 只有休息时可以打开 | 完整整理、长线补给、烹饪材料、备用工具 |

规则：

- 小背包代表玩家身上能立即触达的装备位。
- 大背包代表完整登山包，攀爬中不允许打开，避免打断动作核心。
- 资源点界面可以和小背包并排显示；休息界面可以同时显示小背包和大背包。
- 道具使用优先从小背包扣除；小背包没有时，攀爬中不能自动从大背包扣除。
- 在休息点可以在小背包和大背包之间自由整理物品。

### 2.2 网格规则

| 参数 | 小背包 | 大背包 |
|---|---:|---:|
| 宽度 | 4 格 | 6 格 |
| 高度 | 4 格 | 6 格 |
| 总格数 | 16 格 | 36 格 |
| 允许旋转 | 是 | 是 |
| 允许堆叠 | 由物品定义 | 由物品定义 |
| 攀爬中打开 | 是 | 否 |
| 休息时打开 | 是 | 是 |

### 2.3 基本操作

| 操作 | 输入 | 规则 |
|---|---|---|
| 拖拽物品 | 鼠标左键按住拖动 | 拖到目标格，如果形状占用范围有效且没有冲突，则可以放置 |
| 放置物品 | 松开左键 | 有位置则放入；无位置则回到原位置 |
| 旋转物品 | 拖拽中按 R | 物品按 90 度旋转，实时刷新可放置预览 |
| 快速移动 | F | 在当前界面允许的容器之间快速放入/放出 |
| 打开子菜单 | 右键物品 | 弹出“使用 / 丢弃 / 详情” |
| 使用 | 右键子菜单选择使用 | 根据物品 `UseTiming` 判断当前能否使用 |
| 丢弃 | 右键子菜单选择丢弃 | 从当前容器移除，必要时二次确认 |
| 详情 | 右键子菜单选择详情 | 显示该道具作用说明 3 秒 |

放置反馈：

- 可放置格显示绿色或高亮边框。
- 不可放置格显示红色或冲突阴影。
- 旋转后如果越界或冲突，不能落下。
- 堆叠物品拖到同类堆叠上时，优先合并到堆叠上限。

### 2.4 快速移动规则

F 键快速移动遵循“当前界面上下文”：

| 当前界面 | F 的作用 |
|---|---|
| 小背包常规界面 | 不做跨容器移动，只可后续扩展为快捷使用 |
| 资源点界面 | 从资源点快速放入小背包；若小背包满，则尝试放入当前可访问的大背包，只有休息资源点才允许 |
| 休息界面 | 在小背包和大背包之间快速转移 |
| 丢弃/地面界面 | 从背包快速放出到地面或丢弃区 |

快速移动优先级：

1. 合并已有堆叠。
2. 找到第一个可放置位置。
3. 尝试旋转后找位置。
4. 全部失败则播放失败反馈并保持原位置。

建议类名：`InventoryGrid`


- 所有变更后触发 `Changed` 事件，HUD 和 UI 订阅刷新。

## 5. 运行时系统

### 5.1 PlayerInventory

挂在玩家对象上，作为背包系统入口。

职责：

- 保存小背包 `SmallBackpackGrid`。
- 保存大背包 `LargeBackpackGrid`。
- 根据当前状态判断哪些容器可访问。
- 计算总重量和重量等级。
- 提供工具消耗接口。
- 提供消耗品使用接口。
- 向 HUD 提供摘要数据。

关键接口：

```csharp
public InventoryGrid SmallBackpack { get; }
public InventoryGrid LargeBackpack { get; }
public bool IsLargeBackpackAccessible { get; }
public bool TryConsumeTool(ToolKind toolKind);
public bool HasTool(ToolKind toolKind);
public int GetToolCount(ToolKind toolKind);
public bool TryUseItem(InventoryItemStack item);
public bool TryQuickTransfer(InventoryItemStack item, InventoryContainerKind targetKind);
public float HoldDrainMultiplier { get; }
public float KickForceMultiplier { get; }
```

道具消耗规则：

- 攀爬中使用锚点/攀山绳，只能从小背包扣除。
- 休息界面整理时可以把大背包内的锚点/攀山绳移动到小背包。
- HUD 显示的可用工具数量默认显示“小背包内可立即使用数量”。

重量倍率：

| 重量等级 | 条件建议 | `HoldDrainMultiplier` | `KickForceMultiplier` |
|---|---|---:|---:|
| Light | 0% 到 40% 负重 | 1.00 | 1.00 |
| Medium | 40% 到 70% 负重 | 1.10 | 1.00 |
| Heavy | 70% 到 100% 负重 | 1.25 | 0.90 |
| Overloaded | 超过 100% 负重 | 1.40 | 0.80 |

### 5.2 ToolController 接入

目标：

- 装备工具时先检查小背包中是否有对应物品。
- 使用成功后扣除对应物品。
- 数量不足时 HUD 提示“没有可用锚点”或“没有可用攀山绳”。

推荐流程：

1. 玩家按 W 进入工具模式。
2. 滚轮切换 `ToolKind`。
3. `ToolController.TryUseTool()` 判断落点有效。
4. 调用 `PlayerInventory.TryConsumeTool(selectedTool)`。
5. 扣除成功后生成锚点/绳索。
6. 生成成功后关闭工具模式。

注意：扣除物品应发生在落点校验之后，避免误消耗。

### 5.3 PlayerClimbController 接入

需要新增读取：

- `PlayerInventory.HoldDrainMultiplier`
- `PlayerInventory.KickForceMultiplier`

改动点：

- `DrainStaminaWhileHolding()` 中，普通抓取消耗乘以重量倍率。
- `UpdateKickInput()` 中，蹬腿力乘以重量倍率。
- 小背包打开时可以暂停或冻结攀爬输入，避免 UI 操作和攀爬鼠标操作冲突。
- 不要让背包系统直接控制 `Rigidbody`。

### 5.4 PlayerVitals 接入

新增物品效果：

```csharp
public void ApplyItemEffect(ItemEffect effect);
public void ModifyHealth(float delta);
public void ModifyHunger(float delta);
public void ModifyWarmth(float delta);
public void ModifySanity(float delta);
public void ModifyStamina(float delta);
```

建议约束：

- 食物主要恢复饥饿。
- 医疗主要恢复健康。
- 燃料主要在长休息提高温暖。
- 镇定药恢复理智。

## 6. 资源点搜索系统

### 6.1 ResourceNode

建议脚本：`ResourceNode.cs`

| 字段 | 类型 | 说明 |
|---|---|---|
| `NodeId` | `string` | 存档唯一 id |
| `NodeType` | `ResourceNodeType` | 资源点类型 |
| `LootTable` | `LootTableDefinition` | 掉落表 |
| `CanHarvestOnce` | `bool` | 默认 true |
| `SearchInterval` | `float` | 默认 1 秒 |
| `PromptText` | `string` | 交互提示 |
| `HasSearched` | `bool` | 是否已搜索 |

### 6.2 搜索界面规则

打开资源点界面后：

1. 资源点先根据掉落表生成本次物品列表。
2. 玩家只能看到所有物品的轮廓，不能看到名称、数量和效果。
3. 系统自动开始搜索资源。
4. 每 1 秒搜索 1 个物品。
5. 被搜索完成的物品从轮廓变为完整图标，并显示名称和数量。
6. 玩家只能操作搜索完成的物品。
7. 未搜索完成的物品不能拖拽、不能 F 快速移动、不能右键打开子菜单。
8. 玩家可以提前关闭资源点界面，未搜索完成的物品保持未知或按设计丢失。

### 6.3 搜索状态

资源点内每个物品使用 `ResourceItemSearchState`：

| 状态 | 显示 | 可操作 |
|---|---|---|
| Hidden | 不显示，或只显示空格 | 否 |
| Searching | 显示轮廓和搜索进度 | 否 |
| Revealed | 显示完整图标、名称、数量 | 是 |
| Taken | 从资源点移除 | 否 |

### 6.4 资源点交互流程

1. 玩家进入资源点范围。
2. HUD 显示“搜索资源点”。
3. 按交互键打开资源点界面。
4. 资源点物品以轮廓形式出现。
5. 系统按 `SearchInterval = 1` 秒逐个揭示物品。
6. 玩家对已揭示物品执行左键拖拽、F 快速移动、右键子菜单。
7. 资源点界面关闭时记录已拿走物品和搜索进度。

## 7. 掉落表与高价值资源

建议类名：`LootTableDefinition`

结构：

- 固定掉落：保证基础补给。
- 随机掉落：增加路线变化。
- 高价值额外掉落：独立低概率判定。

示例：

| 资源点 | 固定掉落 | 随机掉落 | 高价值额外 |
|---|---|---|---|
| 食物包 | 普通食物 x1 | 普通食物 x1，概率 50% | 高能压缩口粮，概率 10% |
| 工具箱 | 锚点包 x1 | 攀山绳，概率 25% | 高级锚点包，概率 8% |
| 医疗箱 | 小医疗包 x1 | 镇定药，概率 25% | 医疗包，概率 8% |
| 燃料箱 | 燃料罐 x1 | 普通食物 x1，概率 25% | 保温燃料罐，概率 8% |
| 矿脉 | 可售矿物 x1 | 无 | 稀有遗物，概率 5% |

高价值资源规则：

- 每个区域最多 1 到 2 个高价值资源成功出现。
- 不刷新。
- 不作为主线通关必需。
- 可以提供更高恢复、更轻重量、更高售卖价值或更强安全性。

## 8. 右键子菜单与详情提示

### 8.1 子菜单

右键已揭示或背包内物品，打开子菜单：

| 选项 | 条件 | 效果 |
|---|---|---|
| 使用 | 物品 `UseTiming` 允许当前场景使用 | 调用 `PlayerInventory.TryUseItem()` |
| 丢弃 | 当前界面允许丢弃 | 从容器移除；关键物品可禁用丢弃 |
| 详情 | 总是可用 | 显示物品作用说明 3 秒 |

子菜单规则：

- 子菜单打开时，点击空白处关闭。
- 对资源点未搜索完成物品禁用右键菜单。
- 不可使用的物品，“使用”置灰并显示不可用原因。

### 8.2 详情提示

详情提示内容来自 `InventoryItemDefinition.Description`。

显示规则：

- 显示时长：3 秒。
- 显示位置：物品附近浮层或 HUD 右侧提示区。
- 新详情触发时覆盖旧详情。
- 文案要直接说明作用，不写背景废话。

示例：

| 物品 | 详情文案 |
|---|---|
| 普通食物 | 恢复少量饥饿。 |
| 小医疗包 | 恢复健康，可在非攀爬状态使用。 |
| 锚点包 | 提供锚点。锚点抓取和保持不消耗体力。 |
| 攀山绳 | 发射后生成可抓取绳点，抓取和保持不消耗体力。 |
| 燃料罐 | 长休息时用于烹饪或提高温暖。 |

## 9. 烹饪与补给

烹饪由休息系统进入。玩家在休息菜单点击“烹饪”后打开烹饪菜单；短休息点禁用烹饪，长休息点允许烹饪。

### 9.1 CookingRecipe

建议脚本/数据：`CookingRecipeDefinition`

| 字段 | 类型 | 说明 |
|---|---|---|
| `Id` | `string` | 配方 id |
| `DisplayName` | `string` | 中文名 |
| `RequiredItems` | item/count | 所需物品 |
| `RequiredRestType` | `RestPointType` | 通常为长休息 |
| `Effects` | `ItemEffect[]` | 完成后效果 |

### 9.2 成品版配方建议

| 配方 | 消耗 | 效果 |
|---|---|---|
| 热食 | 普通食物 x1 + 燃料罐 x1 | 饥饿 +35，温暖 +15，理智 +5 |
| 简易补给餐 | 普通食物 x2 | 饥饿 +45 |
| 保温休整 | 保温燃料罐 x1 | 温暖 +25，理智 +10 |
| 急救处理 | 小医疗包 x1 | 健康 +25 |
| 完整急救 | 医疗包 x1 | 健康 +50，理智 +10 |

实现建议：

- 烹饪只在长休息点开放。
- 配方效果直接调用 `PlayerVitals`。
- 物品消耗和效果应用要么同时成功，要么都不发生。

## 10. 背包 UI

### 10.1 必要界面

| 界面 | 出现时机 | 功能 |
|---|---|---|
| HUD 背包摘要 | 常驻 | 显示重量等级、小背包锚点数量、小背包绳索数量 |

## 12. 最小可实现顺序

### 第 1 步：双容器背包数据

- `InventoryItemDefinition`
- `InventoryItemStack`
- `InventoryGrid`
- `PlayerInventory`
- 小背包 4x4。
- 大背包 6x6。
- 验证放置、旋转、堆叠、快速转移、移除。

### 第 2 步：背包 UI 操作

- 左键拖拽。
- 拖拽中 R 旋转。
- F 快速移动。
- 右键子菜单。
- 详情提示显示 3 秒。

### 第 3 步：道具消耗接入

- `ToolController` 使用锚点/绳索前检查小背包。
- 成功放置后扣除小背包物品。
- HUD 显示小背包锚点/绳索数量。

### 第 4 步：重量影响攀爬

- 计算小背包 + 大背包总重量。
- 保持体力消耗乘以重量倍率。
- 蹬腿力乘以重量倍率。
- HUD 显示轻装/中载/重载/超载。

### 第 5 步：资源点逐秒搜索

- `ResourceNode`
- 掉落表。
- 资源点物品轮廓显示。
- 每 1 秒揭示 1 个物品。
- 只允许操作已揭示物品。

### 第 6 步：长休整理和烹饪

- 休息点打开大背包。
- 小背包和大背包之间整理。
- 烹饪消耗物品并恢复长期状态。
- 保存背包和资源点状态。

## 13. 风险与处理

| 风险 | 表现 | 处理 |
|---|---|---|
| 双背包增加 UI 工作量 | 影响攀爬核心完成 | 先做功能型格子 UI，小背包优先，大背包只在休息界面出现 |
| F 快速移动规则混乱 | 玩家不知道物品去了哪里 | 只按当前界面上下文移动，并播放目标容器反馈 |
| 资源搜索等待过长 | 玩家觉得被迫等 UI | 每秒 1 个物品，资源点物品数量控制在 3 到 6 个 |
| 重量惩罚太强 | 玩家觉得资源都是负担 | 中载只轻微惩罚，重载才明显影响 |
| 高价值资源破坏平衡 | 稀有物品让路线过于简单 | 限制每区域出现上限，不让其必需 |
| ToolController 和背包耦合过深 | 后续难维护 | 通过 `PlayerInventory.TryConsumeTool()` 接口隔离 |

## 14. 验收标准

- 小背包 4x4 可以随时打开。
- 大背包 6x6 只能在休息时打开。
- 左键拖拽物品可以在有效位置放置。
- 拖拽中按 R 可以 90 度旋转物品并影响占格。
- F 可以按当前界面上下文快速放入或放出物品。
- 右键子菜单包含“使用 / 丢弃 / 详情”。
- 详情会显示物品作用说明 3 秒。
- 资源点打开后先显示轮廓，每 1 秒揭示 1 个物品。
- 未搜索完成的资源点物品不能被操作。
- 锚点和攀山绳必须从小背包数量中消耗。
- 背包重量能实际影响保持体力消耗和蹬腿效率。
- 高价值资源不出现时，熟练玩家仍可约 10 分钟通关。
